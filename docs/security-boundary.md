# 执行权限边界说明

## 本阶段目标

本阶段只实现最小权限边界，不实现复杂权限系统。

重点是：

- 默认边界清晰
- 高风险动作默认不放开
- 权限约束能进入最终 prompt
- 如果已有项目配置，则优先尊重已有配置

## 默认允许项

- 查看代码
- 修改代码
- 运行测试
- 读取文档

## 默认禁止项

- `git push`
- 自动部署生产
- 危险删除（例如 `rm -rf` 关键目录）

## 高风险动作处理策略

如遇高风险操作：

1. 不允许默认直接执行
2. 必须在结果中明确报告
3. 由人工确认后再决定下一步

## 权限落点

### 1. controller 决策

controller 负责给 worker 下发：

- `repoPath`
- `branchBase`
- 执行边界描述

这些字段不允许来自用户任务文本。

### 2. worker 复核

worker 执行前再次校验：

- 项目路径存在
- 目标项目属于当前 task 的 `projectKey`
- server 连接地址合法

### 3. OpenCode session 权限规则

SDK 模式下，在 `session.create()` 时注入最小权限规则：

- `edit` 允许
- `bash` 默认 `ask`
- `git push*` 拒绝
- `*deploy*` 拒绝
- `rm -rf *` 拒绝
- `external_directory` 拒绝

## 如果项目已有权限配置怎么办

本阶段实现遵循以下策略：

1. 先读取项目已有规则文件作为参考
2. worker 仍然追加本阶段的最小安全禁止项
3. 不擅自覆盖更严格的现有规则

## 推荐配置方式

如果项目还没有清晰的规则配置，建议：

1. 在仓库根目录维护 `AGENTS.md`
2. 在其中明确禁止：
   - `git push`
   - 生产部署
   - 危险删除
3. 对需要人工确认的动作明确写出“必须报告，不可擅自执行”

## 当前边界说明

这不是完整权限系统，而是本阶段的最小可用安全约束。

它的目标是：

- 让 worker 能真实执行研发任务
- 同时避免默认越界到推送、生产部署、危险删除
