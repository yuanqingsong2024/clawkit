## M1 - MVP 稳定

**目标日期**：2026-08-31  
**目标版本**：v0.3.x  
**前置条件**：v0.2.x 完成

### 交付内容

1. **版本统一**
   - 所有 package.json 版本一致
   - CLI 版本号正确显示
   - 发布流程规范

2. **技术债务清理**
   - 编译产物不混入源码
   - 文档与代码同步
   - CI/CD 配置完成

3. **测试覆盖达标**
   - CLI 命令层测试覆盖率 > 60%
   - shared 包测试覆盖率 > 70%
   - E2E 自动化测试覆盖核心链路

4. **功能增强**
   - 配置热重载可用
   - WebSocket 实时日志可用
   - 任务历史页面可用

### 验收标准

```
✅ 单机模式所有功能可正常演示
✅ smoke-test 全项通过
✅ 无 P0/P1 级已知问题
✅ 文档完整度 > 90%
```

## M2 - 生产就绪

**目标日期**：2026-12-31  
**目标版本**：v1.0.0  
**前置条件**：M1 完成

### 交付内容

1. **多 worker 支持**
   - 支持 10+ worker 并发执行
   - 智能负载均衡
   - 任务优先级调度

2. **SSH 部署自动化**
   - 代码同步自动化
   - systemd 服务管理
   - 远程节点健康检查

3. **高可用架构**
   - 多实例部署支持
   - 单点故障不影响服务
   - 监控与告警

4. **安全加固**
   - API 鉴权完善
   - HTTPS 支持
   - 敏感信息加密

### 验收标准

```
✅ 支持 100 并发任务
✅ SSH 节点一键部署完整可用
✅ 安全扫描通过
✅ 关键操作有完整审计日志
✅ 文档完整度 > 95%
```

## 风险与调整

### 可能影响里程碑的因素

| 风险 | 对里程碑的影响 | 应对措施 |
|-----|--------------|---------|
| 核心开发者离开 | M2/M3 延期 | 完善文档，知识传承 |
| OpenCode/Claude Code 变化 | 架构调整 | 抽象执行器接口 |
| 市场需求变化 | 优先级调整 | 保持灵活性 |
| 技术难题 | 延期 1-2 月 | 预留 buffer |

### 调整机制

1. 每季度评审里程碑状态
2. 根据实际进展调整后续计划
3. 重大变更需团队共识
