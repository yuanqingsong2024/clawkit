### T-010：配置热重载

| 属性 | 值 |
|-----|---|
| 任务 ID | T-010 |
| 优先级 | P0 |
| 状态 | 🔴 待开始 |
| 预计工时 | 8h |
| 负责人 | - |

**任务描述**
实现配置文件热重载，修改 manifest 后无需重启 controller

**当前问题**
- manifest 保存后不会自动刷新运行态
- 需要手动重启 controller/worker

**验收标准**
- [ ] 修改 manifest 文件后自动重新加载
- [ ] 不中断当前运行的任务
- [ ] 新增 worker 配置自动生效
- [ ] 提供手动触发重载的 API

**技术方案**
```
方案 A: 文件监听
- 使用 chokidar 监听 manifest 文件变化
- 变化时重新加载并校验
- 动态更新内存中的配置

方案 B: API 触发
- 提供 POST /api/config/reload 接口
- 人工触发重载
- 更可控但需手动操作
```

推荐方案 A + B 结合

**涉及文件**
- `packages/controller/src/services/config.service.ts`（新建）
- `packages/controller/src/http/routes/system-routes.ts`
- `packages/worker/src/config.ts`

### T-011：WebSocket 实时日志

| 属性 | 值 |
|-----|---|
| 任务 ID | T-011 |
| 优先级 | P0 |
| 状态 | 🔴 待开始 |
| 预计工时 | 12h |
| 负责人 | - |

**任务描述**
实现 WebSocket 实时日志流，前端可实时查看任务执行日志

**当前问题**
- 无实时日志推送
- 前端需刷新页面查看新日志

**验收标准**
- [ ] WebSocket 连接稳定
- [ ] 任务执行日志实时推送
- [ ] 支持日志级别过滤（info/warn/error）
- [ ] 断线自动重连

**技术方案**
```
Controller 侧:
- 添加 WebSocket 端点 /ws/logs
- 订阅任务执行事件
- 转发日志到客户端

Worker 侧:
- 执行时实时输出日志
- 通过 HTTP 或消息队列回传
- Controller 聚合后推送

前端侧:
- 使用 React 组件管理 WebSocket
- 实时渲染日志列表
- 支持滚动和搜索
```

**涉及文件**
- `packages/controller/src/http/ws/logs.ws.ts`（新建）
- `packages/worker/src/logger.ts`
- `packages/web/src/components/LogViewer.tsx`（新建）
