# clawkit 架构设计

## 概述

clawkit 是一个用于一键部署、配置并串联 OpenClaw 与 OpenCode 的轻量工具。

## 系统架构

### 核心组件

```
┌─────────────────────────────────────────────────────────┐
│                       clawkit CLI                        │
│                    (用户交互入口)                         │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                      Controller                          │
│                   (任务调度与管理)                        │
└─────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────┐
│                        Worker                            │
│                    (任务执行节点)                         │
└─────────────────────────────────────────────────────────┘
                            │
                ┌───────────┴───────────┐
                ▼                       ▼
        ┌──────────────┐        ┌──────────────┐
        │  OpenClaw    │        │  OpenCode    │
        └──────────────┘        └──────────────┘
```

### 组件说明

#### CLI (packages/cli)
- 用户交互入口
- 命令解析与分发
- 配置文件管理
- 不包含业务逻辑

#### Controller (packages/controller)
- 任务调度中心
- 节点管理
- 状态监控
- 健康检查

#### Worker (packages/worker)
- 任务执行节点
- 与 OpenClaw/OpenCode 交互
- 任务状态上报

#### Shared (packages/shared)
- 类型定义
- 工具函数
- 常量配置

#### Templates (packages/templates)
- 配置模板
- 不包含逻辑代码

## 部署拓扑

### 1. 单机模式 (All-in-One)

```
┌─────────────────────────────────────┐
│          单台机器                    │
│  ┌─────────────────────────────┐   │
│  │ OpenClaw + OpenCode         │   │
│  └─────────────────────────────┘   │
│  ┌─────────────────────────────┐   │
│  │ Controller + Worker         │   │
│  └─────────────────────────────┘   │
└─────────────────────────────────────┘
```

适用场景：
- 本地开发测试
- 小规模部署
- 资源受限环境

### 2. 混合模式 (Hybrid)

```
┌─────────────────────┐      ┌─────────────────────┐
│     云端机器        │      │     本地机器        │
│  ┌──────────────┐   │      │  ┌──────────────┐   │
│  │  OpenClaw    │   │      │  │  OpenCode    │   │
│  └──────────────┘   │      │  └──────────────┘   │
│  ┌──────────────┐   │      │  ┌──────────────┐   │
│  │ Controller   │   │◄────►│  │   Worker     │   │
│  └──────────────┘   │      │  └──────────────┘   │
└─────────────────────┘      └─────────────────────┘
```

适用场景：
- 云端管理，本地执行
- 数据安全要求高
- 网络隔离环境

### 3. 双机模式 (Split)

```
┌─────────────────────┐      ┌─────────────────────┐
│      A 机器         │      │      B 机器         │
│  ┌──────────────┐   │      │  ┌──────────────┐   │
│  │  OpenClaw    │   │      │  │  OpenCode    │   │
│  └──────────────┘   │      │  └──────────────┘   │
│  ┌──────────────┐   │      │  ┌──────────────┐   │
│  │ Controller   │   │◄────►│  │   Worker     │   │
│  └──────────────┘   │      │  └──────────────┘   │
└─────────────────────┘      └─────────────────────┘
```

适用场景：
- 分布式部署
- 负载均衡
- 高可用需求

## 技术选型

### 语言与运行时
- TypeScript：类型安全，开发体验好
- Node.js 20+：稳定的 LTS 版本

### 构建工具
- pnpm：快速、节省空间的包管理器
- TypeScript Compiler：官方编译器

### 项目结构
- Monorepo：统一管理多个包
- pnpm workspace：依赖共享与版本管理

## 设计原则

### 1. 最小可用
- 优先实现核心功能
- 避免过度设计
- 渐进式增强

### 2. 模块化
- 清晰的职责划分
- 松耦合设计
- 易于扩展

### 3. 类型安全
- 严格的 TypeScript 配置
- 完整的类型定义
- 编译时错误检查

### 4. 简单直接
- 避免复杂抽象
- 代码易读易维护
- 文档齐全
