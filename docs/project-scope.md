# clawkit 项目范围

## 项目定位

clawkit 是一个**轻量级**部署工具，专注于简化 OpenClaw 与 OpenCode 的部署与配置流程。

## 核心目标

### 做什么

1. **简化部署**
   - 提供一键部署命令
   - 自动处理依赖关系
   - 支持多种部署拓扑

2. **配置管理**
   - 提供配置模板
   - 支持配置验证
   - 简化配置切换

3. **基础运维**
   - 服务启停管理
   - 状态查看
   - 简单健康检查

### 不做什么

1. **不是完整的运维平台**
   - 不实现复杂的监控系统
   - 不实现完整的日志分析
   - 不实现复杂的告警系统

2. **不是 PaaS 平台**
   - 不实现多租户
   - 不实现资源隔离
   - 不实现计费系统

3. **不是 CI/CD 工具**
   - 不实现自动化测试
   - 不实现自动化构建
   - 不实现自动化发布流程

4. **不是配置中心**
   - 不实现配置版本管理
   - 不实现配置审计
   - 不实现配置回滚

## 功能边界

### 第一阶段边界

**包含**：
- CLI 基础命令
- 单机模式部署
- 配置文件解析
- 基础健康检查

**不包含**：
- Web UI
- 混合/双机模式
- 自动重启
- 性能监控
- 权限系统

### 第二阶段边界

**包含**：
- 混合模式部署
- 双机模式部署
- 节点间通信
- 配置切换

**不包含**：
- Web UI
- 负载均衡
- 自动故障转移
- 分布式锁

### 第三阶段边界

**包含**：
- 简单 Web UI
- 自动重启
- 基础监控
- 日志查看

**不包含**：
- 复杂权限系统
- 多租户支持
- 审计日志
- 性能分析

## 用户画像

### 目标用户

1. **开发者**
   - 需要快速搭建本地开发环境
   - 熟悉命令行操作
   - 对配置有一定了解

2. **小团队**
   - 需要简单的部署方案
   - 资源有限
   - 不需要复杂功能

### 非目标用户

1. **大型企业**
   - 需要完整的运维平台
   - 需要复杂的权限管理
   - 需要审计和合规

2. **云服务提供商**
   - 需要多租户支持
   - 需要资源隔离
   - 需要计费系统

## 技术边界

### 支持的环境

- **操作系统**：Linux、macOS（Windows 待定）
- **Node.js**：20.x LTS
- **OpenClaw**：待定版本范围
- **OpenCode**：待定版本范围

### 不支持的环境

- 旧版本 Node.js（< 20）
- 容器编排（Kubernetes）
- 无服务器（Serverless）

## 复杂度控制

### 代码复杂度

- 单个函数不超过 50 行
- 单个文件不超过 300 行
- 避免深层嵌套（最多 3 层）
- 避免复杂的设计模式

### 依赖复杂度

- 最小化外部依赖
- 优先使用 Node.js 内置模块
- 新增依赖需要评估必要性

### 配置复杂度

- 配置项保持最少
- 提供合理默认值
- 配置验证清晰

## 质量标准

### 代码质量

- TypeScript 严格模式
- 完整的类型定义
- 中文注释
- 清晰的错误信息

### 文档质量

- 每个功能有使用说明
- 每个阶段有验收标准
- 架构变更同步更新文档

### 用户体验

- 命令简单直观
- 错误信息清晰
- 配置易于理解

## 决策原则

### 功能决策

遇到新功能需求时，问自己：
1. 这是核心功能吗？
2. 用户真的需要吗？
3. 会增加多少复杂度？
4. 有更简单的替代方案吗？

### 技术决策

遇到技术选型时，问自己：
1. 这是必需的吗？
2. 会引入多少依赖？
3. 维护成本如何？
4. 有更简单的方案吗？

## 范围变更

### 何时扩展范围

- 用户强烈需求
- 不增加显著复杂度
- 符合项目定位
- 有充足资源

### 何时拒绝需求

- 超出项目定位
- 显著增加复杂度
- 有其他工具可替代
- 资源不足

## 总结

clawkit 是一个**轻量级**、**专注**、**简单**的部署工具。

我们：
- 专注于部署和配置
- 保持简单和直接
- 渐进式增强功能
- 控制复杂度

我们不：
- 做大而全的平台
- 实现所有功能
- 追求技术复杂度
- 过度设计
