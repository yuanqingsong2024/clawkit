# v1.0.0 已知限制

## 文档目的

本文用于说明 **clawkit v1.0.0 在内部试运行阶段的已知限制**。

这些内容的作用不是降低预期，而是避免把当前版本明确保留的边界误判成缺陷。试运行期间应把“当前不支持”“当前不建议”和“实际故障”区分开来。

---

## 一、当前不支持

以下能力在 v0.1.1 **当前不支持**，不应作为本轮内部试运行的验收目标。

### 1. 当前仅适合内部试运行

- 说明：v0.1.0 定位是内部首发级 MVP，用于验证最小主链路是否可用。
- 影响：适合小范围、可控环境试运行，不适合作为正式对外平台或大规模生产系统。

### 2. 不支持复杂权限系统

- 说明：当前没有完整的角色、组织、审批权限体系。
- 影响：不适合多人、多角色、强隔离的正式协作场景。

### 3. 不支持多租户

- 说明：当前没有租户隔离、租户级配置边界、租户级资源治理能力。
- 影响：内部试运行应在单团队、单上下文环境中进行，不应混合多团队正式使用。

### 4. 不支持复杂调度

- 说明：当前 worker 侧具备最小注册、心跳、pull、result 主链路，但不包含复杂多 worker 策略调度、抢占、优先级编排等能力。
- 影响：试运行应以“最小可执行链路”验证为主，不要用它承担复杂资源调度任务。

### 5. 不支持自动 PR

- 说明：当前任务执行链路不包含自动创建或管理 Pull Request 的产品能力。
- 影响：试运行中即使任务执行完成，也不应把“自动出 PR”作为结果预期。

### 6. 不支持自动生产部署

- 说明：`apply` 负责最小文件写入、备份和启动脚本生成，不负责自动上线生产业务代码。
- 影响：试运行期间若涉及真实环境动作，必须由执行人明确控制并手工确认。

### 7. 页面能力仍偏最小可用

- 说明：Web Console 当前定位是轻量可视化外壳，不是复杂管理后台。
- 影响：可以承担内部试运行的查看、确认、基础操作，但不应期待完整运维平台能力。

### 8. 某些高级体验留待后续版本

- 说明：例如复杂图表、实时日志流、复杂节点管理、多层级通知与更细颗粒度引导等，当前均未纳入 v0.1.0。
- 影响：试运行期间如果感觉"还不够顺手"，需要先判断这是不是当前明确未做的内容，而不是直接判定为 bug。

### 9. Manifest 保存后不会自动刷新运行态

- 说明：Web Console 保存 manifest 后，controller/worker 不会自动重新加载配置。
- 影响：
  - 页面显示的配置与实际运行态可能短时间不一致
  - 用户可能误以为"保存了就生效"
- 规避方法：
  - 保存 manifest 后，手动重启 controller 和 worker 进程
  - 或通过 CLI 重新执行 `apply` 命令
- 后续版本计划：后续版本将支持配置热重载。

---

## 二、当前不建议

以下做法不是绝对不可能，但 **v0.1.1 当前不建议** 在内部试运行中采用。

### 1. 不建议把链路联调结果等同于真实 OpenCode 验证结果

- 说明：`node ./scripts/e2e-local-demo.js` 默认允许 placeholder fallback。
- 影响：它适合验证主链路打通，但不能单独证明真实 OpenCode 执行已经过严格验收。

### 2. 不建议把 Web Console 当作完整运维后台使用

- 说明：当前页面支持总览、配置、部署、修复、状态、任务中心，但功能边界明确。
- 影响：试运行期间可以依赖它做主入口，但遇到复杂排查仍应结合 CLI、API 和日志。

### 3. 不建议在当前阶段做复杂远程环境编排

- 说明：混合模式和双机模式当前保留了明确的人工步骤边界。
- 影响：若试运行目标是验证“全自动远程编排”，那会超出 v0.1.0 的真实能力边界。

### 4. 不建议把 manifest 保存视为热更新

- 说明：保存 manifest 只是写文件，不会自动刷新 controller、worker 和 OpenCode 运行态。
- 影响：若配置修改后未重启相关服务，运行结果与页面配置不一致是可预期现象，不应直接当成系统异常。

### 5. 不建议扩大到高风险真实环境

- 说明：当前版本更适合内部可控环境、可回滚场景。
- 影响：试运行应优先在本地、测试机或低风险内部环境验证，不要直接承接正式生产任务。

---

## 三、这些限制对试运行的直接影响

1. **试运行目标要聚焦**：重点验证最小主链路，而不是把所有未来能力一次性验完。
2. **结果判断要分层**：主链路通过，不代表高级体验已经成熟；页面可用，不代表运维后台完备。
3. **问题归类要准确**：属于当前已知限制的，应记录影响和建议；属于偏离文档或阻塞主链路的，才应优先进入修复清单。
4. **扩大范围要谨慎**：只有在主链路、文档可跟随性、页面基本可用性都稳定后，才适合扩大内部试运行范围。

---

## 四、试运行建议

建议按以下原则使用 v0.1.0：

补充说明：

- v0.1.1 起，controller 默认启用 SQLite 持久化。
- 默认数据库路径：`data/clawkit.db`
- 可通过环境变量 `CONTROLLER_DB_PATH` 自定义数据库文件路径。
- 可通过环境变量 `CONTROLLER_ENABLE_PERSISTENCE=false` 显式关闭持久化并退回内存模式。

1. 先在 **单机模式** 完成主链路验证，再补充混合模式说明验证。
2. 把 **链路联调** 与 **真实 OpenCode 执行验证** 分开记录和复盘。
3. 遇到问题先判断：是当前不支持、当前不建议，还是实际故障。
4. 试运行期间优先修正文档漂移、错误提示不清、主链路阻塞问题，不在当前阶段扩架构。
5. 若试运行后发现高频问题集中在文档、页面反馈或主链路稳定性，应优先进入 **v0.1.1 修复**，而不是继续扩大范围。
