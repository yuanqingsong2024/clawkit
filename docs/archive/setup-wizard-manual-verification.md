# Setup 向导手动验证清单

本文档用于验证表单式 Setup 向导的最小可用版本实现。

## 验证环境准备

1. 确保已执行 `pnpm build`
2. 启动 controller：`node ./packages/controller/dist/index.js`
3. 访问 Web Console：`http://localhost:8787`（或配置的端口）
4. 进入 Setup 向导页面

---

## 验证路径 1：all-in-one 表单模式

### 步骤
1. 打开 Setup 页面
2. 确认默认进入"表单模式"
3. 选择 `all-in-one` 拓扑
4. 填写必要字段：
   - 配置名称：`test-all-in-one`
   - Controller 端口：`8787`
   - OpenClaw 地址：`http://127.0.0.1:8787`
   - Worker ID：`local-worker`
   - 项目 key：`clawkit`
   - 仓库路径：`.`
   - OpenCode 端口：`4096`
5. 点击"先校验配置"按钮
6. 确认看到"配置校验通过"提示
7. 确认 YAML 预览区域显示标准化 manifest
8. 点击"确认并启动部署"
9. 观察执行状态：
   - 步骤状态实时更新
   - 日志流正常显示
   - 最终显示执行摘要

### 预期结果
- ✅ 表单字段正确显示
- ✅ 校验通过
- ✅ YAML 预览正确
- ✅ 启动成功
- ✅ 状态展示正常

---

## 验证路径 2：hybrid 表单模式

### 步骤
1. 切换到 `hybrid` 拓扑
2. 填写基础字段（同 all-in-one）
3. 填写额外的云端节点字段：
   - 控制面节点名称：`cloud-control`
   - SSH 主机：`claw.example.com`
   - SSH 端口：`22`
   - SSH 用户：`deploy`
   - SSH 私钥路径：`~/.ssh/id_ed25519`
   - 远程工作目录：`/srv/clawkit/control`
4. 点击"先校验配置"
5. 确认看到 YAML 预览
6. 点击"确认并启动部署"
7. 观察执行流程

### 预期结果

## 验证路径 5：失败场景

### 场景 A：表单校验失败
1. 在表单模式留空必填字段（如配置名称）
2. 点击"先校验配置"
3. 确认看到"表单校验失败"错误提示
4. 确认错误信息清晰指出缺失字段

### 场景 B：preview 失败
1. 填写不合法的 URL（如 `invalid-url`）
2. 点击"先校验配置"
3. 确认看到后端返回的校验错误

### 场景 C：run 失败
1. 使用不可达的 `publicUrl`
2. 启动部署
3. 确认看到：
   - 某个步骤失败（如 check_controller）
   - 步骤错误信息
   - 最终错误摘要
   - 重试按钮可用

### 预期结果
- ✅ 表单校验错误清晰
- ✅ preview 失败有明确提示
- ✅ run 失败有步骤状态和错误摘要
- ✅ 重试功能正常

## 已知限制

1. **split 拓扑**：仅支持 YAML 模式，不支持表单化编辑
2. **高级字段**：runtime/notify/deploy 配置需在 YAML 模式手动编辑
3. **多 worker/project**：当前表单仅支持单 worker 单 project
4. **YAML → 表单回填**：仅支持 all-in-one 和 hybrid，split 会阻止切换
