# Dispatch Check Skill

## 技能说明

此技能用于决策任务是否应该委派给其他 AI 代理，以及选择合适的委派方式。

## 适用场景

- 收到新任务时
- 任务复杂度评估
- 资源分配决策
- 并行任务规划

## 决策框架

### 1. 任务复杂度评估

#### 简单任务（自己做）
- 单文件修改
- 简单的类型修复
- 文档更新
- 配置调整

**特征**：
- 涉及文件 ≤ 2 个
- 代码行数 ≤ 50 行
- 无需探索代码库
- 无需外部知识

#### 中等任务（考虑委派）
- 多文件协调
- 新功能实现
- 重构任务
- 集成测试

**特征**：
- 涉及文件 3-5 个
- 代码行数 50-200 行
- 需要理解现有模式
- 可能需要查文档

#### 复杂任务（必须委派）
- 架构设计
- 跨包重构
- 性能优化
- 复杂调试

**特征**：
- 涉及文件 > 5 个
- 代码行数 > 200 行
- 需要深度探索
- 需要专业知识

### 2. 委派类型选择

#### 类型 A：探索型（explore）
**适用场景**：
- 不熟悉的代码库
- 需要查找模式
- 需要理解架构
- 需要定位问题

**示例**：
- "找出所有使用 Controller 的地方"
- "分析现有的错误处理模式"
- "定位性能瓶颈"

#### 类型 B：知识型（librarian）
**适用场景**：
- 需要查阅文档
- 需要外部知识
- 需要最佳实践
- 需要库的用法

**示例**：
- "如何使用 commander.js"
- "Node.js 进程管理最佳实践"
- "TypeScript 类型守卫用法"

#### 类型 C：执行型（quick/deep）
**适用场景**：
- 明确的实现任务
- 有清晰的规格
- 需要专注执行
- 需要质量保证

**示例**：
- "实现 init 命令"
- "修复类型错误"
- "添加单元测试"

#### 类型 D：咨询型（oracle）
**适用场景**：
- 架构决策
- 技术选型
- 复杂问题诊断
- 设计评审

**示例**：
- "应该使用什么进程管理方案"
- "如何设计节点间通信协议"
- "这个架构有什么问题"

### 3. 并行度评估

#### 串行执行
**适用场景**：
- 任务有依赖关系
- 需要前一步的结果
- 资源受限

**示例**：
```
1. 探索现有代码 → 2. 设计方案 → 3. 实现功能
```

#### 并行执行
**适用场景**：
- 任务相互独立
- 可以同时进行
- 加速整体进度

**示例**：
```
并行：
- 探索 CLI 模式
- 探索配置解析模式
- 查阅 commander.js 文档
```

```

    ↓

└───────────────────────────────┘
    ↓
┌───────────────────────────────┐
│ 需要探索代码库？               │

│ └─ 否 → 继续评估              │
└───────────────────────────────┘
    ↓
┌───────────────────────────────┐
│ 需要外部知识？                 │
│ ├─ 是 → librarian (并行)      │
│ └─ 否 → 继续评估              │
└───────────────────────────────┘
    ↓
┌───────────────────────────────┐
│ 需要架构决策？                 │
│ ├─ 是 → oracle                │

    ↓
┌───────────────────────────────┐
│ 任务复杂度？                   │
│ ├─ 简单 → quick               │
│ └─ 复杂 → deep                │
└───────────────────────────────┘
```

## 决策示例

### 示例 1：实现 init 命令

**任务**：实现 `clawkit init` 命令

**分析**：
- 复杂度：中等（新功能，多文件）
- 需要探索：是（需要了解 CLI 模式）
- 需要外部知识：是（commander.js 用法）
- 需要决策：否

**决策**：
```typescript
// 第一步：并行探索和学习
task(subagent_type="explore", run_in_background=true, 
     description="探索 CLI 模式")
task(subagent_type="librarian", run_in_background=true,
     description="学习 commander.js")

// 第二步：等待结果后实现
task(category="quick", load_skills=[],
     description="实现 init 命令")
```

### 示例 2：修复简单类型错误

**任务**：修复 Controller 的类型错误

**分析**：
- 复杂度：简单（单文件，类型修复）
- 需要探索：否
- 需要外部知识：否
- 需要决策：否

**决策**：
```typescript
// 自己做
read("packages/controller/src/index.ts")
lsp_diagnostics("packages/controller/src/index.ts")
// 修复...
```

### 示例 3：设计节点通信协议

**任务**：设计 Controller 和 Worker 的通信协议

**分析**：
- 复杂度：复杂（架构决策）
- 需要探索：是（现有代码结构）
- 需要外部知识：是（通信协议最佳实践）
- 需要决策：是（技术选型）

**决策**：
```typescript
// 第一步：并行探索和学习
task(subagent_type="explore", run_in_background=true,
     description="探索现有架构")
task(subagent_type="librarian", run_in_background=true,
     description="学习 Node.js 进程间通信")

// 第二步：咨询架构决策
task(subagent_type="oracle", run_in_background=false,
     description="设计通信协议")

// 第三步：实现
task(category="deep", load_skills=[],
     description="实现通信协议")
```

### 示例 4：添加文档

**任务**：为 CLI 添加使用文档

**分析**：
- 复杂度：简单（文档编写）
- 需要探索：否（已知功能）
- 需要外部知识：否
- 需要决策：否

**决策**：
```typescript
// 自己做
write("packages/cli/README.md", content)
```

## 委派提示词模板

### 探索型（explore）

```markdown
[CONTEXT]: 我正在实现 [功能]，需要了解现有的 [模式/结构]
[GOAL]: 找出 [具体要找的内容]，以便 [如何使用]
[DOWNSTREAM]: 我将使用这些信息来 [具体行动]
[REQUEST]: 
- 查找：[具体内容]
- 重点关注：[关注点]
- 跳过：[不需要的内容]
- 返回格式：[期望格式]
```

### 知识型（librarian）

```markdown
[CONTEXT]: 我正在实现 [功能]，需要使用 [库/技术]
[GOAL]: 了解 [具体知识点]，以便 [如何应用]
[DOWNSTREAM]: 我将使用这些知识来 [具体行动]
[REQUEST]:
- 查找：[官方文档/最佳实践/示例]
- 重点：[关注的方面]
- 跳过：[不需要的内容]
```

### 执行型（quick/deep）

```markdown
# 任务：[任务名称]

## 1. 任务目标
[目标]

## 2. 预期产出
[产出]

## 3. 必须使用的工具
[工具列表]

## 4. 必须遵守的规则
[规则]

## 5. 禁止的行为
[禁止事项]

## 6. 上下文信息
[上下文]

## 7. 验证要求
[验证]
```

### 咨询型（oracle）

```markdown
# 咨询：[问题]

## 背景
[项目背景和当前状态]

## 问题
[具体要咨询的问题]

## 约束条件
[技术约束、资源约束等]

## 期望
[期望得到什么样的建议]
```

## 决策检查清单

在委派前，检查：

- [ ] 任务目标是否明确？
- [ ] 是否真的需要委派？
- [ ] 选择的代理类型是否合适？
- [ ] 提示词是否足够详细？
- [ ] 是否设置了明确的约束？
- [ ] 是否可以并行执行？
- [ ] 是否有验证标准？

## 常见错误

### ❌ 过度委派
```typescript
// 错误：简单任务也委派
task(category="quick", description="修改一个变量名")
```
**正确**：自己做

### ❌ 委派类型错误
```typescript
// 错误：用 explore 做实现
task(subagent_type="explore", description="实现 init 命令")
```
**正确**：用 quick/deep

### ❌ 串行执行独立任务
```typescript
// 错误：串行执行可并行的任务
task(subagent_type="explore", run_in_background=false, ...)
task(subagent_type="librarian", run_in_background=false, ...)
```
**正确**：并行执行

### ❌ 提示词不明确
```typescript
// 错误：目标模糊
task(description="改进 CLI")
```
**正确**：明确具体目标

## 与其他技能的配合

- **task-intake** → **dispatch-check**：任务明确后决策是否委派
- **dispatch-check** → **prompt-draft**：决定委派后起草提示词
- **dispatch-check** → 直接执行：决定自己做就直接执行

## 总结

好的委派决策：
- 评估准确
- 类型匹配
- 并行优先
- 提示明确
- 验证清晰

避免：
- 过度委派
- 类型错误
- 串行浪费
- 提示模糊
- 缺少验证
