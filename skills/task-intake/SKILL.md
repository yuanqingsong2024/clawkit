# Task Intake Skill

## 技能说明

此技能用于接收和理解用户的任务请求，将模糊的需求转化为明确的任务描述。

## 适用场景

- 用户提出新的功能需求
- 用户报告 bug
- 用户询问如何实现某个功能
- 需求不够明确时

## 工作流程

### 1. 理解需求

**输入**：用户的原始请求

**处理**：
- 识别请求类型（功能、修复、咨询等）
- 提取关键信息
- 识别隐含需求
- 发现模糊点

**输出**：需求理解摘要

### 2. 明确范围

**问题清单**：
- 这个任务的目标是什么？
- 涉及哪些组件/文件？
- 有哪些约束条件？
- 预期的交付物是什么？
- 验收标准是什么？

### 3. 确认阶段

**检查**：
- 是否符合当前阶段目标？
- 是否在项目范围内？
- 是否需要拆分为多个任务？

### 4. 输出任务描述

**格式**：
```markdown
## 任务类型
[功能开发/Bug修复/重构/文档/其他]

## 任务目标
[一句话描述要达成什么]

## 涉及范围
- 组件：[列出涉及的 package]
- 文件：[列出可能涉及的文件]
- 依赖：[列出可能的新依赖]

## 详细需求
[详细描述需求]

## 验收标准
- [ ] 标准1
- [ ] 标准2
- [ ] 标准3

## 风险与注意事项
- 风险1
- 风险2

## 预估工作量
[小/中/大]
```

## 示例

### 示例 1：功能需求

**用户输入**：
> 我想添加一个命令来查看所有服务的状态

**任务描述输出**：
```markdown
## 任务类型
功能开发

## 任务目标
实现 `clawkit status` 命令，显示所有服务的运行状态

## 涉及范围
- 组件：@clawkit/cli, @clawkit/controller
- 文件：packages/cli/src/commands/status.ts (新建)
- 依赖：可能需要进程管理库

## 详细需求
1. 添加 status 命令到 CLI
2. 查询 controller、worker、openclaw、opencode 的运行状态
3. 以表格形式展示：服务名、状态、PID、运行时间
4. 如果服务未运行，显示 "未运行"

## 验收标准
- [ ] 执行 `clawkit status` 可以看到所有服务状态
- [ ] 状态信息准确
- [ ] 输出格式清晰易读
- [ ] 服务未运行时有明确提示

## 风险与注意事项
- 需要确定如何获取进程状态（PID 文件？进程查询？）
- 跨平台兼容性（Linux/macOS）
- 当前阶段是否应该实现此功能

## 预估工作量
中
```

### 示例 2：Bug 报告

**用户输入**：
> 构建失败了，提示找不到某个类型

**任务描述输出**：
```markdown
## 任务类型
Bug修复

## 任务目标
修复构建失败问题

## 涉及范围
- 需要先定位问题
- 可能涉及类型定义文件

## 详细需求
1. 复现构建失败
2. 查看完整错误信息
3. 定位缺失的类型定义
4. 补充类型定义或修复引用

## 验收标准
- [ ] `pnpm build` 执行成功
- [ ] 无类型错误
- [ ] 所有 package 正常构建

## 风险与注意事项
- 需要先看到完整错误信息才能确定修复方案

## 预估工作量
小（假设是简单的类型问题）
```

## 使用指南

### 何时使用此技能

- ✅ 用户需求不够明确
- ✅ 需要拆分复杂任务
- ✅ 需要确认理解是否正确
- ✅ 需要评估任务范围

### 何时不使用此技能

- ❌ 需求已经非常明确
- ❌ 简单的一句话任务
- ❌ 紧急的小修复

## 输出要求

1. **明确性**：任务描述必须清晰明确
2. **可执行性**：开发者看到后知道如何开始
3. **可验证性**：有明确的验收标准
4. **完整性**：包含所有必要信息

## 注意事项

1. 不要假设用户的意图，有疑问就询问
2. 考虑当前项目阶段的限制
3. 识别超出范围的需求
4. 评估技术可行性
5. 考虑对现有代码的影响

## 与其他技能的配合

- **task-intake** → **prompt-draft**：任务明确后，起草实现提示
- **task-intake** → **dispatch-check**：检查任务是否应该委派
